# Telegram-бот

Бот обслуживает два типа сценариев: клиентские действия с личной картой и операторские кассовые операции. Роли определяются по Telegram ID: активный оператор находится через `operators.telegram_id`, остальные пользователи работают как клиенты.

## Команды в меню Telegram

Глобальное меню команд получает только клиентские команды:

| Команда | Назначение | Ограничения |
| --- | --- | --- |
| `/start` | Показать стартовое сообщение и reply-клавиатуру. | Для активного оператора показывается операторская клавиатура, для клиента — клиентская. |
| `/balance [код]` | Показать баланс. | Без кода использует текущую привязанную карту. С кодом показывает публичный баланс карты. |
| `/my_card` | Показать текущую карту клиента с QR и балансом. | Нужен Telegram account. Если карты нет, бот предлагает создать или привязать карту. |
| `/create_my_card` | Создать личную карту или вернуть уже существующую. | У клиента может быть только одна текущая карта. |
| `/link [код]` | Привязать существующую карту. | Если код не указан и QR Mini App настроен, бот просит сканировать QR. Если карта уже привязана к пользователю, бот показывает её и не начинает новую привязку. |
| `/unlink [код]` | Отвязать карту. | Без кода отвязывает текущую карту. После отвязки бот возвращает QR/код карты для восстановления доступа. |
| `/transfer [код]` | Создать одноразовый код передачи карты. | Без кода использует текущую карту. Передать можно только карту текущего владельца. |
| `/accept_transfer <код_передачи>` | Принять карту по коду передачи. | Код должен существовать, не быть использованным и не истечь. |
| `/history [код]` | Показать последние операции. | Без кода использует текущую карту. С кодом история owned card доступна только владельцу или оператору; история карты без владельца публична. |

Операторские команды публикуются отдельно в scope чата каждого активного оператора:

| Команда | Назначение | Ограничения |
| --- | --- | --- |
| `/debit <код> <сумма> [описание]` | Списать сумму с карты напрямую. | Только активный оператор. Сумма должна быть больше нуля. После операции бот просит чек. |
| `/debit <сумма> [описание]` | Начать списание через QR-сканирование карты. | Только активный оператор. Требует настроенный QR Mini App для кнопки сканирования; иначе бот просит ввести код вручную. |
| `/credit <код> <сумма> [описание]` | Пополнить карту напрямую. | Только активный оператор. Сумма должна быть больше нуля. После операции бот просит чек. |
| `/credit <сумма> [описание]` | Начать пополнение через QR-сканирование карты. | Только активный оператор. Требует настроенный QR Mini App для кнопки сканирования; иначе бот просит ввести код вручную. |
| `/create_gift_card <начальная_сумма>` | Создать подарочную карту. | Только активный оператор. Начальная сумма должна быть больше нуля. После создания бот просит чек. |

## Reply-клавиатура

Reply-клавиатура появляется после `/start` и в сценариях QR-сканирования.

Для клиента всегда доступны:

- `💳 Баланс`
- `📋 История`
- `🎟️ Моя карта`

Если у клиента есть привязанная карта, дополнительно показывается:

- `⛓️ Отвязать карту`

Если у клиента нет привязанной карты, показываются:

- `➕ Создать мою карту`
- `🔗 Привязать карту`

Если состояние привязки определить не удалось, бот показывает оба варианта: создание, привязку и отвязку. Это запасной режим для нештатной ситуации.

Для активного оператора reply-клавиатура содержит клиентские действия и операторские действия:

- `➖ Списать`
- `➕ Пополнить`
- `➕ Создать подарочную карту`

Операторские кнопки всё равно проверяют права через `requireBotOperator`; если Telegram ID больше не является активным оператором, операция не запускается.

## QR Mini App

QR Mini App используется для сканирования кодов карт и чеков, если задан `WEB_APP_URL`.

Если `WEB_APP_URL` не задан, бот не показывает web app кнопку и отвечает текстом с ручным fallback: пользователь или оператор вводит код карты или причину пропуска чека сообщением.

QR карты содержит plain text `cards.code`. QR чеков разбирается как фискальный QR payload; если чек не удалось прочитать или приложить, оператор может отправить причину пропуска.

## Чеки после операторских операций

После создания подарочной карты, списания или пополнения бот сохраняет операцию и просит оператора приложить чек.

Оператор может:

- отсканировать QR бумажного или электронного фискального чека;
- отправить причину пропуска: `нечитаемый QR`, `чек потерян`, `касса без QR`, `техническая ошибка`, `другое <комментарий>`.

Статусы чеков отображаются в истории операций. Клиент видит статусы и ссылки на чеки для `DEBIT` и `CREDIT`; причины пропуска и комментарии предназначены для операторского/административного разбора.
